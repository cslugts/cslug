# Database

PostgreSQL only, through `Bun.sql`. Tables are TypeScript, row types are inferred, single-table queries use a
small typed builder, everything else is tagged SQL with typed results. Migrations are SQL files. Transactions
are ambient. **No ORM, no dependency.**

## Tables

```ts
// app/tables/operator-table.ts
import { table, id, uuid, text, boolean, numeric, integer, timestamp, timestamps, softDeletes, type Row } from '@cslug/database'
import { users } from '#app/tables/user-table'

export const operators = table('operators', {
  id: id(),                                                   // uuid, primary key, UUIDv7 generated by the app
  userId: uuid().references(() => users, { onDelete: 'restrict' }),
  companyName: text(),
  licenceNumber: text().unique(),
  email: text().unique(),
  phone: text(),
  verificationStatus: text().oneOf(['pending', 'in_review', 'verified', 'suspended']).default('pending'),
  payoutMethod: text().oneOf(['mvola', 'orange_money', 'airtel_money', 'bank']),
  payoutAccount: text().encrypted(),                         // AES-256-GCM with APP_KEY; decrypted on read; not searchable
  maxSeats: integer().default(4),
  ratingAvg: numeric(3, 2).nullable(),                       // returned as string (exact), not float
  acceptsNightDriving: boolean().default(false),
  verifiedAt: timestamp().nullable(),
  ...timestamps(),                                           // createdAt, updatedAt (timestamptz)
  ...softDeletes(),                                          // deletedAt
}, {
  indexes: (t) => [t.index('verificationStatus'), t.index('userId')],
})

export type Operator = Row<typeof operators>          // what a SELECT returns
```

`Row<T>` is the type of a selected row. `NewRow<T>` is the type of an insert: columns that are `NOT NULL` without
a default are required, while columns with a default (`id`, `timestamps()`, `.default(…)`) or `.nullable()` are
optional. `Repository.create()` takes a `NewRow`, so you rarely write it yourself. Export one only when your own
code passes insert data around, for example a service method or an import script:

```ts
import type { NewRow } from '@cslug/database'
export type NewOperator = NewRow<typeof operators>

async importFromSheet(rows: NewOperator[]) { await this.operators.createMany(rows) }
```

### Rules

- **Columns are `NOT NULL` unless `.nullable()`.** Nullable columns are `T | null` in the row type.
- TS property names are camelCase and SQL names are snake_case (`companyName` ↔ `company_name`), mapped both ways.
- `.oneOf([...])` narrows the type to a union **and** adds a `CHECK` constraint.
- `bigint` columns (`amount()`, `bigint()`) are `bigint` in TS. `numeric` is `string` (exact decimal).
  `date()` is a `'YYYY-MM-DD'` string. `timestamp()` is `Date` (UTC, `timestamptz`).

### Column builders

| Builder | SQL | TS |
|---|---|---|
| `id()` | `uuid primary key` | `string` (UUIDv7, generated on insert) |
| `uuid()` | `uuid` | `string` |
| `text()` / `varchar(n)` | `text` / `varchar(n)` | `string` (or union with `.oneOf`) |
| `integer()` / `bigint()` | `integer` / `bigint` | `number` / `bigint` |
| `numeric(p, s)` | `numeric(p,s)` | `string` |
| `boolean()` | `boolean` | `boolean` |
| `date()` | `date` | `string` (`'2027-05-14'`) |
| `timestamp()` | `timestamptz` | `Date` |
| `jsonb<T>()` | `jsonb` | `T` |
| `amount()` | `bigint` | `bigint` (money, minor units) |
| `currency()` | `char(3)` | `Currency` (ISO 4217 union) |
| `shortCode('ALB')` | `text unique` | `string` (`ALB-7K2Q9F`, generated on insert) |
| `translated()` | `jsonb` | `{ fr?: string; en?: string; it?: string }` |
| `timestamps()` / `softDeletes()` | `created_at`, `updated_at` / `deleted_at` | `Date` / `Date \| null` |

Modifiers: `.nullable()`, `.default(v)`, `.defaultSql(sql\`now()\`)`, `.unique()`, `.references(() => t, opts)`,
`.oneOf([...])`, `.encrypted()` (text columns; cannot appear in `where`), `.check(sql\`…\`)`.

Columns PostgreSQL computes, and indexes beyond btree:

```ts
export const products = table('products', {
  id: id(),
  name: text(),
  price: numeric(10, 2),
  qty: integer().default(1),
  total: numeric(12, 2).generatedAs((c) => `${c('price')} * ${c('qty')}`),     // generated always as (…) stored
  search: custom('tsvector')
    .generatedAs((c) => `to_tsvector('simple', ${c('name')})`)
    .hidden(),                                                                  // not in selects, not in Row
}, { indexes: (t) => [t.using('gin', 'search'), t.using('gin', ['name', 'gin_trgm_ops'])] })
```

- `.generatedAs((c) => expression)`: `c('key')` gives a sibling column's SQL name. Inserts and updates leave the
  column out (even when a whole row is passed back), and it is not part of `NewRow`. The differ creates it, and when
  the expression changes it emits `alter column … set expression` (PostgreSQL 17+), tracked by a hash in the column
  comment.
- `.hidden()`: left out of every select (`Row` does not have it); still usable in `whereSql`, `orderBySql` and
  indexes. For large derived values such as a search vector.
- `custom<T>('tsvector')` is a column of any other PostgreSQL type.
- `t.using('gin', 'search')` builds `<table>_<columns>_<method>_idx` with that access method; `['name',
  'gin_trgm_ops']` gives a column an operator class. `@cslug/search` builds on these three.

## Repositories

`Repository(table)` gives a typed base. Add domain queries as methods.

```ts
// app/repositories/operator-repository.ts
import { inject } from '@cslug/core'
import { Repository, sql, gte, inList } from '@cslug/database'
import { operators, type Operator } from '#app/tables/operator-table'
import { operatorCircuits } from '#app/tables/operator-circuit-table'

@inject()
export class OperatorRepository extends Repository(operators) {
  /** Single-table: the builder. */
  pendingReview() {
    return this.where({ verificationStatus: inList(['pending', 'in_review']) }).orderBy('createdAt').all()
  }

  forUser(userId: string) {
    return this.where({ userId }).first()                      // Operator | null
  }

  /** Join: tagged SQL, typed by passing the table. */
  verifiedOn(circuitId: string, minSeats = 1) {
    return this.db.many(sql`
      select ${operators.star}
      from ${operators}
      join ${operatorCircuits} on ${operatorCircuits.c.operatorId} = ${operators.c.id}
      where ${operatorCircuits.c.circuitId} = ${circuitId}
        and ${operators.c.verificationStatus} = 'verified'
        and ${operators.c.maxSeats} >= ${minSeats}
        and ${operators.c.deletedAt} is null
      order by ${operators.c.ratingAvg} desc nulls last`, operators)     // → Promise<Operator[]>
  }
}
```

### Built-in methods

| Method | Returns |
|---|---|
| `find(id)` / `findOrFail(id)` | `Operator \| null` / `Operator` (throws `NotFoundError`) |
| `findBy(where)` / `findByOrFail(where)` | first match |
| `existsBy(where)` / `count(where?)` | `boolean` / `number` |
| `create(values)` / `createMany(values[])` | inserted row(s) (`RETURNING *`) |
| `update(id, values)` | updated row; `updatedAt` set automatically |
| `upsert(values, { conflict: ['email'], update: ['phone'] })` | row |
| `delete(id)` | soft delete when the table has `deletedAt`; `forceDelete(id)` otherwise |
| `lockForUpdate(id, { skipLocked?, noWait? })` | row, `SELECT … FOR UPDATE` (inside a transaction) |
| `transition(id, 'status', Status, 'paid', fn?)` | row; locks it, checks the move against a `states()` machine, updates, runs `fn` (below) |
| `paginate({ page, perPage, where?, orderBy? })` | `{ data, meta: { page, perPage, total, lastPage } }` |
| `where(conditions)` | a query (below) |
| `withTrashed()` / `onlyTrashed()` | include / only soft-deleted rows |
| `this.db` | the `Database` (transaction-aware) |

## The query builder (single table)

```ts
import { eq, ne, gt, gte, lt, lte, inList, notIn, like, ilike, between, isNull, notNull, not } from '@cslug/database'

await this.bookings
  .where({
    status: inList(['deposit_paid', 'released_stage_1']),
    startDate: between(from, to),
    operatorId,                                  // shorthand for eq(operatorId)
    cancelledAt: null,                           // IS NULL
  })
  .orWhere({ status: 'proposed', groupSize: gte(6) })
  .orderBy('startDate', 'asc')
  .orderBy('completedAt', 'asc', { nulls: 'first' })   // chainable; nulls: 'first' | 'last'
  .limit(50)
  .all()                                          // Booking[]

await this.bookings.where({ travellerId }).select('id', 'ref', 'status').all()   // Pick<Booking, 'id'|'ref'|'status'>[]
await this.bookings.where({ status: 'requested', createdAt: lt(cutoff) }).update({ status: 'cancelled' })
await this.bookings.where({ id: inList(ids) }).lockForUpdate().all()
await this.bookings.where({ status: 'completed' }).cursor({ after, limit: 100, orderBy: 'id' })   // keyset
for await (const b of this.bookings.where({ status: 'deposit_paid' }).each({ batch: 500 })) { … }  // streams
```

Keys of `where` are checked against the table's columns, and values against the column types.
`.whereSql(sql\`…\`)` adds a raw condition when an operator is missing; `.orderBySql(sql\`…\`)` a raw sort term, and
`.selectSql('rank', sql<number>\`…\`)` a computed value on each row (typed, still paginated):

```ts
const q = sql`websearch_to_tsquery('simple', ${term})`
await this.products.query()
  .whereSql(sql`${products.c.search} @@ ${q}`)
  .selectSql('rank', sql<number>`ts_rank_cd(${products.c.search}, ${q})`)
  .orderBySql(sql`ts_rank_cd(${products.c.search}, ${q}) desc`)
  .paginate(1, 20)                                  // data: (Row & { rank: number })[]
```

## The `sql` tag (everything else)

```ts
const rows = await this.db.many(sql<{ day: string; bookings: number; revenue: bigint }>`
  select date_trunc('day', ${bookings.c.createdAt})::date as day,
         count(*)::int as bookings,
         sum(${bookings.c.commission})::bigint as revenue   -- sum(bigint) is numeric in Postgres: cast it
  from ${bookings}
  where ${bookings.c.createdAt} >= ${since}
  group by 1 order by 1`)
```

| Interpolation | Becomes |
|---|---|
| `${operators}` | `"operators"` (quoted identifier) |
| `${operators.c.companyName}` | `"operators"."company_name"` |
| `${operators.star}` | `"operators".*` (the result is mapped back to camelCase) |
| `${value}` | bound parameter `$n`, never inlined |
| `${sql\`…\`}` | nested fragment |
| `${sql.join(list, sql\`, \`)}` / `${sql.raw('…')}` | lists / trusted literal (lint-flagged) |

Aggregates follow Postgres types: `count(*)` is `bigint` (cast with `::int` for a number) and `sum()` of a
`bigint` column is `numeric` (a string), so cast it back with `::bigint`.

Result typing: pass a table (`db.many(query, operators)`) to map and type rows as `Operator`, or annotate the
tag (`sql<{…}>`) for ad-hoc shapes. `db.one()` (throws if not exactly one), `db.maybeOne()`, `db.many()`,
`db.exec()` (no rows, returns count), `db.value()` (first column of the first row).

There is no API that takes a SQL string, so concatenating user input into SQL is not possible.

## Relations without an ORM: `preload`

```ts
import { preload, belongsTo, hasMany } from '@cslug/database'

const list = await this.bookings.where({ travellerId }).all()
const rows = await preload(list, {
  operator: belongsTo(operators, 'operatorId'),
  milestones: hasMany(milestones, 'bookingId', { orderBy: 'dueAt' }),
})
// rows: (Booking & { operator: Operator; milestones: Milestone[] })[]   — 3 queries total, no N+1
```

## Transactions

```ts
import { Database } from '@cslug/database'

@inject(Database, ClaimRepository, BookingRepository)
export class ClaimService {
  constructor(private db: Database, private claims: ClaimRepository, private bookings: BookingRepository) {}

  async open(bookingId: string, input: OpenClaim) {
    return this.db.transaction(async () => {
      const booking = await this.bookings.lockForUpdate(bookingId)
      const claim = await this.claims.create({ bookingId, ...input })
      await this.bookings.update(booking.id, { hasOpenClaim: true })
      await ClaimOpened.emit({ claimId: claim.id })          // queued listeners wait for COMMIT
      return claim
    })
  }
}
```

- Every repository and `db` call inside the callback uses the transaction; a throw rolls back.
- Nested `transaction()` → savepoint.
- Jobs, queued listeners, mail and notifications dispatched inside are sent **after commit**.
- Explicit style also works: `db.transaction(async (tx) => this.claims.using(tx).create(…))`.
- Options: `{ isolation: 'serializable', retry: 3 }` (retries on serialization failure / deadlock).

### State transitions

A status column with rules (`requested → proposed → accepted`, never back) is a `states()` machine from core, and
`transition()` moves a row through it safely:

```ts
export const ClaimStatus = states({ open: ['escalated', 'resolved'], escalated: ['resolved'], resolved: [] }, {
  name: 'claim',
  onEnter: { escalated: ({ row }) => ClaimEscalated.emit({ claimId: (row as Claim).id }) },
})
export const claims = table('claims', { id: id(), status: text().oneOf(ClaimStatus.values).default('open'), … })

await this.claims.transition(claimId, 'status', ClaimStatus, 'escalated', async (claim, from) => {
  await this.notes.create({ claimId: claim.id, text: `escalated from ${from}` })
})
```

In the ambient transaction (or one of its own): it locks the row, returns it unchanged when it is already in that
state (so retries and duplicate webhooks are harmless), throws `ConflictError('claim.invalid_transition')` (409) on
a move the machine does not allow, then runs the machine's `onLeave` hook, the update, `onEnter`, and your callback.
A throw anywhere rolls everything back.

### Locks and idempotency

```ts
await this.bookings.lockForUpdate(id)                                       // row lock
await this.db.advisoryLock(`payout:${operatorId}`, async () => { … })        // cluster-wide mutex
const transfer = await this.db.idempotent(`release:${bookingId}:1`, () => this.gateway.release(…))
// the first call runs and stores the result; every call with the same key gets it back as JSON
// (Json<T>: bigint and Date become strings, the same shape on the first call and on replays)
```

## Migrations

Plain SQL with `-- up` / `-- down`, so reviewers read exactly what runs.

```bash
cslug make:migration --from-tables     # diff app/tables/ against the database → SQL file
cslug make:migration add_claims_index  # empty file for hand-written SQL
cslug migrate                          # pending migrations; advisory-locked (concurrent runs execute once)
cslug migrate:status
cslug migrate:rollback --step 1        # the last batch by default; --force in production
cslug migrate --seed                   # then run the seeders (--force too in production)
cslug migrate:fresh --seed             # drop everything and migrate again; refused when APP_ENV=production
cslug db:diff                          # show drift between tables and the database, write nothing
cslug db:shell                         # psql on the app database (-c 'select …' for one statement)
```

```
$ cslug make:migration --from-tables
  1. rename
  2. drop+add
operators.phone_number → phone: rename or drop+add?: 1
  ~ column  operators.phone_number → phone
  + column  operators.max_seats integer
  ~ column  operators.rating_avg numeric(3,2) (was numeric(2,1))
! operators.rating_avg: a type change may need `using rating_avg::numeric(3,2)`
✓ database/migrations/20261126_143000_update_operators.sql
```

```sql
-- database/migrations/20261126_143000_update_operators.sql
-- review: operators.rating_avg: a type change may need `using rating_avg::numeric(3,2)`
-- up
alter table operators rename column phone_number to phone;
alter table operators add column max_seats integer not null default 4;
alter table operators alter column rating_avg type numeric(3,2);

-- down
alter table operators alter column rating_avg type numeric(2,1);
alter table operators drop column max_seats;
alter table operators rename column phone to phone_number;
```

The differ covers tables, columns (type, nullability, default), unique/check constraints, indexes and foreign
keys; it reads the tables in `app/tables/` and skips the packages' `cslug_*` tables. Without a terminal (CI), a
possible rename is taken as a rename, which keeps the data; review the file either way. Anything else (views, triggers, data migrations) is hand-written SQL. Each migration runs in its own
transaction unless it starts with `-- cslug:no-transaction` (for `create index concurrently`).

## Factories and seeders

```ts
// database/factories/operator-factory.ts
import { factory } from '@cslug/database'
import { operators } from '#app/tables/operator-table'

export const OperatorFactory = factory(operators, ({ seq, fake }) => ({
  companyName: `Operator ${seq}`,
  licenceNumber: `LIC-${seq}`,
  email: `operator${seq}@example.test`,
  phone: fake.phone('MG'),
  payoutMethod: 'mvola',
  payoutAccount: fake.phone('MG'),
  userId: () => UserFactory.create({ role: 'operator' }).then((u) => u.id),
}))
  .state('verified', { verificationStatus: 'verified', verifiedAt: new Date() })

await OperatorFactory.state('verified').createMany(12)
```

`fake` is a deliberately small built-in (names, emails, phones per country, dates, words, sentences, numbers,
picks, `passwordHash(plain)`) with a seeded RNG, so tests are deterministic.

| Factory API | |
|---|---|
| `factory(table, (ctx) => values)` | `ctx` = `{ seq, fake, clock }`; a value may be a function (lazy, e.g. create a parent) |
| `.state(name, values \| (ctx) => values)` | Named variant; states combine: `.state('dueToday').state('done')` |
| `.for(attrs)` | Fixed attributes for every row, e.g. `.for({ userId: me.id })` |
| `.make(overrides?)` / `.create(overrides?)` / `.createMany(n, overrides?)` | Build without saving / insert |

```ts
// database/seeders/pilot-seeder.ts
export default seeder(async () => {
```

`cslug db:seed` runs `database/seeders/database-seeder.ts`; `cslug db:seed pilot` runs `pilot-seeder.ts` (`--force`
in production). `cslug make:table Claim`, `make:repository Claim`, `make:factory Claim` and `make:seeder Pilot` write
the files with the right names and imports.

## Errors from PostgreSQL

Constraint violations become typed errors, so a duplicate is handled where it matters, without a racy
`existsBy()` first:

```ts
import { UniqueViolationError } from '@cslug/database'

try {
  await this.operators.create(input)
} catch (error) {
  if (error instanceof UniqueViolationError && error.constraint === 'operators_email_key')
    throw new ValidationError({ email: ['validation.unique'] })
  throw error
}
```

| Error | When | Fields |
|---|---|---|
| `QueryError` | Any failed statement | `sqlState`, `constraint`, the SQL text (never the values) in the message, the driver error as `cause` |
| `UniqueViolationError` | `23505` | `constraint` (`<table>_<column>_key`) |
| `SerializationError` | `40001` / `40P01` (serialization failure, deadlock) | retried by `transaction(fn, { retry: 3 })` |
| `RowCountError` | `db.one()` got zero or several rows | |
| `NotFoundError` | `findOrFail`, `findByOrFail`, `update`, `delete` of a missing id | 404 `<resource>.not_found` |

## More on transactions

```ts
// an explicit handle instead of the ambient transaction
await this.db.transaction(async (tx) => {
  await this.claims.using(tx).create(input)
  await tx.exec(sql`update ${bookings} set has_open_claim = true where ${bookings.c.id} = ${input.bookingId}`)
})

// something that must be written even if the transaction rolls back (an attempt log)
await this.db.withoutTransaction(() => this.attempts.create({ bookingId, error: String(error) }))
```

Soft deletes: on a table with `...softDeletes()`, `delete(id)` sets `deletedAt` and queries skip those rows;
`restore(id)` brings one back, `withTrashed()` / `onlyTrashed()` include them, `forceDelete(id)` really deletes.

## Encrypted columns and key rotation

`text().encrypted()` stores the value with AES-256-GCM under `APP_KEY`, decrypts it on read, and refuses it in
`where` (a random IV per value makes it unsearchable: keep a separate hash column if you must look it up). After
`APP_KEY` changes, `cslug db:reencrypt` rewrites every encrypted column with the new key (guide 26).
