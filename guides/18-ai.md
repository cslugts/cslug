# AI

`@cslug/ai` turns AI features into ordinary cslug code: agents and tools are `@inject()` classes, inputs and outputs
are validators, long runs are jobs, tests use a fake. The design is in [docs/ai-readiness.md](../docs/ai-readiness.md).

> The MVP does not include AI features. This guide shows the first ones that would pay off, so the API can be
> judged now and the seams kept in place.

## Configuration

```ts
// config/ai.ts
export default defineConfig({
  default: 'anthropic',
  providers: {
    anthropic: { driver: 'anthropic', apiKey: env.ANTHROPIC_API_KEY },   // promptCaching, fallbacks: on by default
    local: { driver: 'openai-compatible', baseUrl: 'http://localhost:11434/v1' },
  },
  models: {                                   // code refers to roles, never to model IDs
    fast: 'claude-haiku-5-5',
    smart: 'claude-opus-5-5',
  },
})
```

`cslug add ai` installs the package, adds `AiProvider` and writes this file. The Anthropic driver calls the Messages
API with `fetch` (cslug has no third-party runtime dependencies): the system prompt is cached (`promptCaching:
false` to turn it off), and on the models that support them, refusals fall back server-side to another model
(`fallbacks: false` to turn it off). A refusal that is not rescued is an `AiRefusalError`. A daily budget comes with
MCP in the next part of this package.

## Structured output: turning an operator's reply into a comparable offer (MVP #3)

Operators answer trip requests on WhatsApp in free text. The team copies those into a standard proposal by hand.
An agent can draft that step; staff review it.

```ts
// app/validators/operator-offer-schema.ts — shared by the admin form and the agent
export const OperatorOfferSchema = v.object({
  price: v.money(),
  inclusions: v.array(v.enum(['accommodation', 'meals', 'park_fees', 'guide', 'fuel', 'driver'])),
  vehicle: v.object({ type: v.enum(['4x4', 'minibus', 'car']), seats: v.int() }),
  guideLanguages: v.array(v.enum(['fr', 'en', 'it', 'de'])),
  nightDriving: v.boolean().describe('True if any leg is planned after dark'),
  notes: v.string().max(500).optional(),
})
```

```ts
// app/agents/offer-extractor-agent.ts
import { inject } from '@cslug/core'
import { Agent, prompt } from '@cslug/ai'
import { OperatorOfferSchema } from '#app/validators/operator-offer-schema'

@inject()
export class OfferExtractorAgent extends Agent {
  model = 'fast'                                          // a role from config ai.models, or a model ID
  instructions = prompt('proposals/extract-offer')       // resources/prompts/proposals/extract-offer.md
  output = OperatorOfferSchema
}
```

Like jobs, agents declare their settings without `override`: `model`, `instructions`, `output`, `tools`,
`maxSteps` (8), `provider`, `effort`, `maxTokens`. With `output`, the schema becomes the model's structured-output
format (constraints the API does not accept, such as `min` or `max`, are left out of what it is sent) and the
answer is parsed and validated with the full schema.

```ts
const offer = await this.extractor.run({ input: reply.text, context: { currency: tripRequest.budget.currency } })
//    ^? v.infer<typeof OperatorOfferSchema>  — parsed and validated; AiOutputError if the model can't comply
```

Prompts are Markdown files with `{{ variables }}` filled from `context` (a missing one is an error), versioned in
git and listed by `cslug ai:prompts`.

## Tools: letting an agent act through your code

```ts
// app/tools/find-operators-tool.ts
import { inject } from '@cslug/core'
import { Tool } from '@cslug/ai'
import { v } from '@cslug/validation'
import { OperatorRepository } from '#app/repositories/operator-repository'

@inject(OperatorRepository)
export class FindOperatorsTool extends Tool {
  name = 'find_operators'
  description = 'List verified operators for a circuit with rating and vehicle types.'
  input = v.object({ circuitId: v.uuid(), groupSize: v.int().min(1) })

  constructor(private operators: OperatorRepository) { super() }

  async handle({ circuitId, groupSize }: v.infer<this['input']>) {
    const list = await this.operators.verifiedOn(circuitId)
    return list.filter((o) => o.maxSeats >= groupSize).map(operatorTransformer)
  }
}
```

```ts
@inject()
export class TripRequestTriageAgent extends Agent {
  model = 'smart'
  instructions = prompt('trip-requests/triage')
  tools = [FindOperatorsTool, CircuitDetailsTool]
  output = v.object({ circuitId: v.uuid(), shortlist: v.array(v.uuid()).max(3), questionsForTraveller: v.array(v.string()) })
  maxSteps = 6
}
```

Tools run with the **current user's** permissions (they can call `auth.authorize`), inside the agent run's scope.
Their input is validated before `handle` runs; an invalid input or a thrown error goes back to the model as an
error result, so it can correct itself. All the calls of one turn run together and go back in one message.

## Long runs are jobs

```ts
@inject(TripRequestRepository, TripRequestTriageAgent, ProposalService)
export class DraftProposalJob extends Job<{ tripRequestId: string }> {
  static queue = 'ai'
  static tries = 2
  constructor(
    private tripRequests: TripRequestRepository,
    private agent: TripRequestTriageAgent,
    private proposals: ProposalService,
  ) { super() }

  async handle({ tripRequestId }) {
    const tripRequest = await this.tripRequests.findOrFail(tripRequestId)
    const draft = await this.agent.run({ input: describeTripRequest(tripRequest) })
    await this.proposals.saveDraft(tripRequestId, draft, { reviewedBy: null })    // staff must approve
  }
}
```

## Streaming to a page

```ts
async assist({ request }: HttpContext) {
  const { question } = await request.validate(v.object({ question: v.string().max(500) }))
  return sse(this.visaAssistant.stream({ input: question }))     // text deltas as server-sent events
}
```

`sse` comes from `@cslug/ai`: each piece of text is a `data:` line (a JSON string), the end is `event: done`, a
failure `event: error`. The stream keeps the request's context (user, scope) while the model answers; tools run
between the streamed turns.

## MCP

> Coming in the next part of `@cslug/ai` (with `ai:record`, `ai:eval` and the budget).

Expose tools to external AI clients (staff using Claude Desktop, partner agents):

```ts
@inject()
@mcp({ guard: 'token', ability: 'mcp:bookings' })
export class BookingStatusTool extends Tool { … }
```

```bash
cslug mcp:serve --transport=http      # streamable HTTP at /mcp, token-authenticated
cslug mcp:serve --transport=stdio     # local
```

Use an external MCP server from an agent: `tools = [...mcp('maps').tools(['route_duration'])]`.

## Testing

```ts
const app = testApp({ fakes: ['ai'] })
app.ai.respond(OfferExtractorAgent, { price: { amount: 210000n, currency: 'EUR' }, inclusions: ['guide'], … })

await app.resolve(DraftProposalJob).handle({ tripRequestId })
app.ai.assertRan(OfferExtractorAgent, (run) => run.input.includes('Isalo'))
```

`respond()` answers are checked against the agent's `output` schema, so fixtures stay valid; an agent with no answer
fails with the line to add.

*Coming next:* `cslug ai:record` runs a test against the real provider once and stores the response as a fixture, so the
suite stays fast and deterministic. `cslug ai:eval proposals` runs a folder of fixtures through the real model and
reports schema failures and diffs, which keeps prompt changes reviewable.
