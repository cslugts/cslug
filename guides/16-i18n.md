# Internationalisation

The example app launches in **French, English and Italian**. Translations, locale detection, and money/date formatting
use the same keys everywhere. `t()` from `@cslug/core` is for TS code; `useT()` from `@cslug/vue` is for views,
components, islands and mail.

## Translation files

```
resources/lang/
  fr.json   en.json   it.json
  fr/circuits.json …         # optional split per domain; merged under the file name
```

```json
// resources/lang/fr.json
{
  "bookings": {
    "created": "Votre demande a bien été reçue.",
    "pay": { "title": "Acompte pour {ref}", "cta": "Payer l'acompte en sécurité" },
    "status": { "deposit_paid": "Acompte versé", "completed": "Voyage terminé" },
    "travellers": "{count, plural, one {# voyageur} other {# voyageurs}}"
  }
}
```

Messages use ICU syntax (plurals, select). `cslug i18n:check` reports missing and unused keys per locale.

## Locale detection

```ts
// config/i18n.ts
export default defineConfig({
  locales: ['fr', 'en', 'it'],
  default: 'en',
  fallback: { it: 'en', fr: 'en' },
  detect: ['route', 'user', 'cookie', 'header'],      // /:locale param → user.locale → cookie → Accept-Language
})
```

The `locale()` middleware sets the ambient locale for the request; jobs and mail carry the locale they were
dispatched with (or the recipient's).

## Server

```ts
import { t, formatMoney, formatDate } from '@cslug/core'

t('bookings.created')
t('bookings.pay.title', { ref: booking.ref })
t('bookings.travellers', { count: 3 })
t('bookings.created', {}, 'it')                       // explicit locale
formatMoney(220000n, 'EUR')                           // "2 200,00 €" in fr, "€2,200.00" in en
formatDate(booking.startDate, 'long', { tz: 'Indian/Antananarivo' })
await withLocale('it', () => mailer.to(x).send(m))
```

## Views, components and islands

```vue
<script setup lang="ts">
import { useT, useRequest } from '@cslug/vue'
defineProps<{ groupSize: number }>()
const { t, locale } = useT()
const { alternates } = useRequest()          // the current page in each locale (server only)
</script>

<template>
  <p>{{ t('bookings.travellers', { count: groupSize }) }}</p>
  <nav class="locales">
    <a v-for="alt in alternates" :key="alt.locale" :href="alt.url" :aria-current="alt.locale === locale">{{ alt.locale }}</a>
  </nav>
</template>
```

`useT()` reads the request's locale on the server. In a hydrated island it uses translations embedded in the
page. Only the namespaces an island declares are embedded (`defineOptions({ lang: ['bookings', 'common'] })`),
and only for components hydrated on that page.

## Translated content (circuit pages)

UI strings live in JSON; **content** (circuit descriptions, day-by-day routes) lives in the database with one
column per locale or a translations table:

```ts
export const circuits = table('circuits', {
  id: id(),
  slug: text().notNull().unique(),
  title: translated(),                // jsonb { fr, en, it }, read with tr(circuit.title)
  summary: translated(),
})
```

`tr(value)` picks the current locale with the configured fallback, on the server and in Vue.

## URLs

Public pages are prefixed with the locale (`/fr/circuits/tana-isalo`). `route()` fills in `locale` from the
current one. `useRequest().alternates` lists the current page in every locale; the default layout uses it for
`<link rel="alternate" hreflang>` tags.
