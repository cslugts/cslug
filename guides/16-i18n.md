# Internationalisation

The example app launches in **French, English and Italian**. Translations, locale detection, and money/date formatting
use the same keys everywhere. `t()` from `@cslug/core` is for TS code; `useT()` from `@cslug/vue` is for views,
components, islands and mail.

## Translation files

```
resources/lang/
  fr.json   en.json   it.json
  fr/circuits.json …         # optional split per domain; merged under the file name (circuits.*)
```

```json
// resources/lang/fr.json
{
  "bookings": {
    "created": "Votre demande a bien été reçue.",
    "pay": { "title": "Acompte pour {ref}", "cta": "Payer l'acompte en sécurité" },
    "status": { "deposit_paid": "Acompte versé", "completed": "Voyage terminé" },
    "travellers": "{count, plural, =0 {Aucun voyageur} one {# voyageur} other {# voyageurs}}",
    "guide": "{gender, select, female {Votre guide est arrivée} other {Votre guide est arrivé}}"
  }
}
```

Messages use a subset of ICU: `{name}` placeholders, `plural` (`=0`, `one`, `other`, … with `#` for the number,
by `Intl.PluralRules`), `select`, and nesting. A missing key shows as the key itself, so it is easy to spot.

Error codes are translation keys too: `AppError('payments.declined')`, `ValidationError` messages
(`validation.required`, …) and `ConflictError('booking.invalid_transition')` are shown through `t()` (guides 06, 07).

## Locales and fallbacks

```ts
// config/i18n.ts
import { defineConfig } from '@cslug/core'

export default defineConfig({
  locales: ['fr', 'en', 'it'],
  default: 'en',
  fallback: { it: 'fr' },       // a key missing in Italian is looked up in French, then in the default
})
```

A key is looked up in the locale, then along its `fallback` chain, then in the default locale.

## Locale detection

The `locale()` middleware picks the request's locale, in this order, accepting only `i18n.locales`:

1. the `:locale` route parameter (`/fr/circuits/…`);
2. the `locale` cookie;
3. `Accept-Language` (weighted; `fr-CA` counts as `fr`);
4. the default.

It sets `ctx.locale` and the ambient locale that `t()`, `useT()` and the formatters read. A language switcher sets
the cookie:

```ts
import { type HttpContext, redirect } from '@cslug/http'

async switch({ params, response, request }: HttpContext) {
  const { locale } = await request.validate(v.object({ locale: v.enum(['fr', 'en', 'it']) }))
  response.cookie('locale', locale, { maxAge: 60 * 60 * 24 * 365 })
  return redirect().back()
}
```

A user's saved language (`users.locale`) is yours to apply: a middleware after `authenticate()` can set
`ctx.locale` from `auth.user()?.locale`.

## Server

```ts
import { currentLocale, formatDate, formatMoney, t, tr, withLocale } from '@cslug/core'

t('bookings.created')
t('bookings.pay.title', { ref: booking.ref })
t('bookings.travellers', { count: 3 })
t('bookings.created', {}, 'it')                       // explicit locale
currentLocale()                                       // 'fr'
formatMoney(220000n, 'EUR')                           // "2 200,00 €" in fr, "€2,200.00" in en (or a Money)
formatDate(booking.startDate, 'long')                 // a 'YYYY-MM-DD' date, shown as is in the locale
formatDate(booking.createdAt, 'short', { tz: 'Indian/Antananarivo' })   // a Date, in a time zone
formatDate(value, { weekday: 'long', day: 'numeric' })                  // or Intl options
await withLocale('it', () => mailer.to(x).send(m))    // everything inside runs in Italian
```

Jobs run in the default locale: pass the locale in the payload when it matters, and wrap the work in
`withLocale(payload.locale, …)`. Mail and notifications are built in the recipient's locale
(`mailer.to(x).locale(x.locale)`, and a recipient's `locale` field), guide 14.

## Views, components and islands

```vue
<script setup lang="ts">
import { formatDuration, useRequest, useT } from '@cslug/vue'
import { Money } from '@cslug/core'
defineProps<{ groupSize: number; drivingMinutes: number; price: Money }>()
const { t, tr, locale, formatMoney, formatDate } = useT()
const { alternates } = useRequest()          // the current page in each locale (server only)
</script>

<template>
  <p>{{ t('bookings.travellers', { count: groupSize }) }}</p>
  <p>{{ formatMoney(price) }} · {{ formatDuration(drivingMinutes) }}</p>   <!-- "2 h 30 min" -->
  <nav class="locales">
    <a v-for="alt in alternates" :key="alt.locale" :href="alt.url" :aria-current="alt.locale === locale">{{ alt.locale }}</a>
  </nav>
</template>
```

`useT()` reads the request's locale on the server. In a hydrated island it uses translations embedded in the
page. Only the namespaces an island declares are embedded (`defineOptions({ lang: ['bookings', 'common'] })`),
and only for components hydrated on that page.

## Translated content

UI strings live in JSON; **content** (circuit descriptions, day-by-day routes) lives in the database. A
`translated()` column holds one value per locale:

```ts
import { id, table, text, translated } from '@cslug/database'

export const circuits = table('circuits', {
  id: id(),
  slug: text().unique(),
  title: translated(),                // jsonb { fr?, en?, it? }
  summary: translated(),
})
```

`tr(circuit.title)` picks the current locale, following the fallback chain, on the server and in Vue; a plain string
is returned as is.

## URLs

Public pages are prefixed with the locale (`/fr/circuits/tana-isalo`), from a group with `prefix: '/:locale'` and
the `locale()` middleware (guide 05). Pass the locale when you build a URL:
`route('public.circuits.show', { locale: ctx.locale, slug })`. `useRequest().alternates` lists the current page in
every locale (for routes with a `:locale` parameter); the default layout uses it for
`<link rel="alternate" hreflang>` tags.

## The translator

`Translator` (injectable) holds the messages: `has(key, locale?)`, `keys(locale)` (to compare two locales in a
test), `add(locale, messages)` (messages from elsewhere: a package, the database), `chain(locale)` (the fallback
order). `validationTranslator(locale?)` turns validation errors into text outside a request:
`error.messages(validationTranslator('fr'))`.

```ts
// tests/i18n.test.ts: every key of the default locale exists in the others
import { expect, test } from 'bun:test'
import { Translator } from '@cslug/core'
const t = Translator.fromDirectory('resources/lang', { locales: ['fr', 'en', 'it'], default: 'en' })
for (const locale of ['fr', 'it']) test(locale, () => expect(t.keys('en').filter((k) => !t.has(k, locale))).toEqual([]))
```

## Reference

```ts
import { t, tr, withLocale, currentLocale, formatMoney, formatDate, Translator, validationTranslator } from '@cslug/core'
import { locale } from '@cslug/http/middleware'
import { useT, useRequest, formatMoney, formatDate, formatDuration } from '@cslug/vue'   // views and islands
import { translated } from '@cslug/database'                             // the column type
```

i18n is in core: nothing to install. Translations are read from `resources/lang/` at boot.
