# AI readiness

"AI-ready" covers two separate things, and cslug addresses both:

1. **AI in the product.** The pilot app will eventually want AI (the MVP excludes an AI trip planner, but turning
   free-text operator replies into a comparable proposal (#3) or triaging WhatsApp check-in replies (#7) are
   obvious next steps). cslug should make those features ordinary code, not a separate stack.
2. **AI on the codebase.** Coding agents (Claude Code and others) will write a large share of the app. cslug
   should make the right code the easiest code for them to produce, and give them a way to inspect the app.

## 1. AI in the product: `@cslug/ai`

### The idea: no new primitives

| AI concept | Is just… |
|---|---|
| Tool input schema | a validator (`v.object(...)`) → JSON Schema via `toJSONSchema()` |
| Structured output | a validator; the result is parsed and typed |
| Tool | an `@inject()` class with `handle(input)`; it can use repositories, policies, cache |
| Agent | an `@inject()` class: model, instructions, tools, output schema |
| Long-running agent run | a `Job` (`ExtractOfferJob.dispatch(...)`), with retries and failure hooks |
| Prompt caching / cost control | `cache.remember()` + the provider's prompt caching, set in config |
| Evaluation | `bun test` with recorded fixtures (`ai.fake()`), see [guides/18](../guides/18-ai.md) |

```ts
@inject()
export class OfferExtractorAgent extends Agent {
  model = config('ai.models.fast')
  instructions = prompt('offers/extract')          // resources/prompts/offers/extract.md
  output = OperatorOfferSchema                     // the same schema the admin form validates
}

const offer = await this.extractor.run({ input: operatorWhatsappReply })
//    ^? OperatorOffer — typed, validated, or throws AiOutputError
```

### Providers

One `AiProvider` with drivers: `anthropic` (default), `openai-compatible` (covers OpenAI, Mistral, local Ollama),
and `fake` for tests. Model names live in `config/ai.ts` under roles (`fast`, `smart`), so code never
hard-codes a model ID.

### MCP

- `cslug mcp:serve` exposes every class tagged as an MCP tool (`@inject(...) @mcp() class X extends Tool`) over
  MCP (stdio or streamable HTTP, behind auth). The same `Tool` class serves the in-app agent and external AI clients.
- `ai.mcp('name')` lets an `Agent` use tools from an external MCP server.

### What is deferred

Multi-step workflows and durable agent runs (a run that waits for a human and resumes). The seams exist (Postgres,
queue, `Tool`), but none of it ships until the product needs it.

Planned ([implementation plan](./implementation-plan.md)): conversations (history in and out, then stored
conversations and run records, M9g), and retrieval with pgvector through `@cslug/search` (M10), which also serves
search outside AI.

## 2. AI on the codebase

| Mechanism | What it gives an agent |
|---|---|
| **Folder + naming conventions** | It knows a file's role from its folder and name (`app/jobs/send-checkin-job.ts`); generators and discovery agree |
| **Generators** (`cslug make:job SendCheckin`) | The canonical shape of every class, so it doesn't invent its own |
| **Types flow end to end** | `bun typecheck` catches wrong code; it doesn't need to guess shapes |
| **`AGENTS.md`** (generated by `cslug agents:sync`, hand-editable sections preserved) | Project conventions, commands, domain glossary, "don't do" list |
| **`cslug describe --json`** | Routes (+ middleware), tables + columns, jobs + queues (+ payload schema), schedules, config keys, providers |
| **`cslug mcp:dev`** | A development MCP server: `describe`, `routes`, `tables`, `query` (read-only, dev DB), `logs`, `last_error`, `run_test`, `docs_search` |
| **Docs shipped with the package** | `node_modules/@cslug/*/docs/` + `llms.txt`, so agents read docs for the installed version |
| **Errors that say how to fix** | e.g. `BindingNotFoundError` names the provider line to add |
| **Fast, isolated tests** | `testApp()` + fakes; an agent can verify a change in seconds |

$ cslug describe routes --json | jq '.[0]'
